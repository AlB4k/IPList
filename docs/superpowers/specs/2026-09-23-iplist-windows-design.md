# IPList 1.4.0 для Windows: архитектурная спецификация

## Статус и цель

Эта спецификация описывает отдельное Windows-приложение IPList 1.4.0 с тем же пользовательским контрактом и результатами обработки, что и macOS-версия IPList 1.4.0. Приложение предназначено для Windows 10 22H2 и Windows 11 на `win-x64`, а его интерфейс должен быть максимально близок к macOS-версии по структуре, названиям и последовательности действий, сохраняя стандартное поведение Windows.

Windows-часть является самостоятельным проектом в каталоге `Windows/`. Swift-код, `Package.swift`, macOS-проект, macOS workflow, macOS состояние пользователя и macOS release assets не входят в область изменений этой реализации.

Цель — воспроизвести функциональное поведение IPList 1.4.0: каталог сервисов, три режима маршрутизации, ручные адреса и группы, профили, обновление источников, enrichment DNS/RIPEstat, историю изменений, JSON AmneziaVPN, `AllowedIPs` и безопасное обогащение AmneziaWG `.conf`.

## Зафиксированные решения

| Область | Решение |
| --- | --- |
| UI | WPF на C# 13 |
| Runtime/SDK | .NET 10 LTS; язык фиксируется через `LangVersion=13.0` |
| ОС | Windows 10 22H2 и Windows 11, `win-x64` |
| Проект | независимый `Windows/`, без ссылки на macOS assembly |
| Хранилище | `%LOCALAPPDATA%\\IPList\\state.json` и соседние служебные файлы |
| Релиз | self-contained ZIP с одним `IPList.exe` и документацией |
| CI | отдельный GitHub Actions workflow на `windows-latest` |
| Установка | не требуется; Store, MSIX и установщик не входят в релиз 1.4.0 |
| Обновление приложения | автообновление не входит в релиз 1.4.0 |
| Архитектуры | только `win-x64`; ARM64 не входит в релиз 1.4.0 |
| Внешние UI-зависимости | не используются |

`windows-latest` подтверждает сборку и автоматические тесты, но сам по себе не доказывает совместимость с Windows 10. До объявления релиза требуется ручная smoke-проверка на чистой Windows 10 22H2 и Windows 11. Неподписанный первый ZIP может показывать предупреждение SmartScreen; code signing не является условием функциональной реализации.

## Границы репозитория

Windows-проект располагается в следующей области:

```text
Windows/
├── IPList.Windows.sln
├── src/
│   ├── IPList.Core/
│   └── IPList.App/
├── tests/
│   └── IPList.Core.Tests/
└── README.md
```

`IPList.Core` — обычная библиотека .NET без ссылок на WPF. Она содержит модели состояния, IPv4/CIDR, каталог, matching, enrichment-контракты, refresh-транзакцию и экспортеры. `IPList.App` содержит WPF-окно, ViewModel, tray, системные диалоги, буфер обмена, уведомления и таймер расписания. `IPList.Core.Tests` проверяет поведение на фиксированных и санитизированных fixtures.

Общий каталог данных не становится вторым macOS-проектом. Windows-сборка получает лицензированные bundled resources из `Resources/ThirdParty` как embedded/content resources с явным source attribution. В Windows publish не копируются `AppIcon.icns`, macOS `.app`, `dist`, macOS app state, пользовательские exports, реальные ключи и `.vpn`-файлы.

## UI и пользовательский контракт

Главное окно сохраняет структуру macOS-версии: узкая левая навигация, крупный заголовок страницы, область статуса, верхние действия «Проверить сейчас» и «Экспорт…», раскрываемые категории и модальные диалоги. Цвета, отступы, названия и порядок разделов должны быть максимально близкими к macOS screenshots. Контролы используют стандартные WPF focus states, клавиатурную навигацию и масштабирование Windows 100–200%.

Навигация содержит пять страниц:

1. **Каталог.** Режимы «Точечный обход», «Компактный IP-список (Lite)», «Полный российский сегмент»; поиск по названию, домену, `AS####`, IP и CIDR; свернутые категории; выбор сервиса, категории, «Все/Снять» и «Выбрать всё»; раскрытие доменов, ASN и маршрутов; отдельный выбор «Остальные сети источника»; «Мои IP»; freshness и evidence remote/cache.
2. **Мои IP.** Включение в выгрузку; добавление IPv4/CIDR, разделённых пробелом, запятой или `;`; нормализация; сообщение о невалидных значениях; группы, заметки, импорт JSON AmneziaVPN с предварительным выбором строк, копирование одного/всех адресов и удаление.
3. **Изменения.** До 100 последних событий с датой, причиной, количеством добавленных и удалённых маршрутов и раскрытием списков. Открытие страницы помечает уведомление просмотренным.
4. **Выгрузка.** Текущий режим и описание, переключатель «Мои IP», отсортированные маршруты и владельцы, число адресов, открытие папки автосохранения, копирование и сохранение `AllowedIPs`, мастер создания AmneziaWG `.conf`, предупреждение для Full.
5. **Настройки.** Режим, активный source URL, профили выбора, интервал автоматического обновления 1–720 часов или ручной режим, последняя проверка, уведомления, четыре редактируемых HTTPS URL, сохранение источников, upstream links и проверка источников с HTTP-кодом, длительностью, числом адресов и сообщением.

Отсутствующий каталог показывает empty state с действием обновления. Занятость refresh видна в верхней панели и не блокирует закрытие окна без необходимости. Ошибки показываются понятным modal alert; исключения и секреты не выводятся в UI или журналы.

## Модель каталога и маршрутов

Каталог содержит стабильный идентификатор, название, категорию, домены, ASN, явные диапазоны и сопоставленные адреса отдельно для `targeted`, `lite` и `full`. Стабильный ID строится из источника и нормализованного имени. Коллизии ID отклоняют кандидат каталога. При переименовании разрешено единственное восстановление выбора по пересечению доменов и ASN; неоднозначное соответствие остаётся без автоматического выбора и попадает в диагностику.

Категории читаются из ограниченного используемого подмножества `config.yaml`: заголовки секций, `services`, `name`, `asn`, `ip_ranges`, `domains`. Неизвестные поля игнорируются. Неопознанная категория сохраняет сервис в «Без категории», а не удаляет его. Парсер ограничивает 4 MiB на response, 2 000 сервисов, 20 000 domains/ranges/ASNs и 512 UTF-8 байт на текстовое поле. Пустой каталог, неверный сервис, коллизия или подозрительное уменьшение относительно последней успешной копии отклоняют refresh.

Записи `amnezia.json`, отсутствующие в каталоге, сохраняются как «Дополнительные ресурсы lib4u». Lite и Full диапазоны, которые нельзя связать с сервисом, видимы через выбранный по умолчанию элемент «Остальные сети источника».

Для каждого сервиса объединяются явные диапазоны, A-записи доменов, RIPEstat announced prefixes и доменные адреса из `amnezia.json`. Для Lite/Full широкая исходная сеть не назначается целиком по одному найденному IP: она разбивается по границам доказанных пересечений. Общий фрагмент может иметь нескольких владельцев. Объединение выбранных сервисов и «Остальных сетей источника» должно быть множеством адресов равно исходному Lite/Full списку. Нельзя публиковать результат, который расширяет source или теряет его адреса.

Снятие галочки исключает собственные адреса сервиса, но общий маршрут остаётся при наличии другого выбранного владельца. Все сервисы и «Остальные сети источника» выбраны на чистой установке. Политика выбора новых ресурсов и существующие профили переносятся без изменения намерений пользователя.

IPv4/CIDR-движок нормализует host bits, проверяет containment/intersection/exact subtraction, объединяет только соседние сети с точно тем же множеством адресов и сортирует результат численно. Bare IP в JSON остаётся bare IP, а в `AllowedIPs` становится `/32`. Ручные IP не отправляются в DNS или RIPEstat.

## Источники, DNS и атомарное обновление

Источники остаются теми же:

- `https://raw.githubusercontent.com/lib4u/amnezia-tunneling-ru/main/amnezia.json`, `amnezia-ip-lite.json` и `amnezia-ip.json`;
- `https://raw.githubusercontent.com/pincetgore/amnezia-app-ru-list/main/config.yaml` как metadata catalog;
- последняя успешная копия и bundled snapshot как fallback;
- RIPEstat `announced-prefixes` API для ASN;
- системный Windows DNS resolver для доменов.

Приложение не отправляет весь каталог в Google, Cloudflare или другой публичный DoH. DNS/RIPEstat enrichment ограничен 8 параллельными запросами, 12 секундами на запрос и 60 секундами на полный refresh. Принимаются ответы до 4 MiB; generated CIDR fragments ограничены 250 000.

«Проверить сейчас» и расписание выполняют одну транзакцию: metadata, три source списка, DNS, RIPEstat и diagnostics собираются во временную модель, валидируются, затем одним атомарным commit заменяют активное состояние. Ошибка сети, парсинга, DNS, RIPEstat, превышение лимита или нарушение source-union сохраняет последнюю успешную модель, выбор, профили и автосохранённую выгрузку. Stale evidence остаётся доступным с датой и явной отметкой stale.

Расписание работает, пока запущено приложение или его tray-процесс. При закрытии окна пользователь может оставить процесс в tray; отключение tray завершает расписание. Повторный запуск не должен запускать параллельные refresh для одного состояния.

## Состояние, миграция и локальные файлы

Основное состояние Windows хранится в `%LOCALAPPDATA%\\IPList\\state.json`. Оно включает каталог и legacy services, выбор сервисов и unassigned per mode, маршруты трёх режимов, source snapshots, DNS/ASN cache, migration diagnostics, manual entries/groups/notes, `manualEnabled`, change history, last checks, interval/automatic, четыре URL, mode, profiles, selection policy, tray/notification flags и unseen changes.

Перед миграцией создаётся `state-before-v1.4.json`. Старое состояние используется только после проверок схемы и не удаляется при неуспешной миграции. Ручные адреса, группы, заметки, история, расписание и профили должны пережить перезапуск. Готовая выгрузка сохраняется как `amnezia-direct.json` только внутри локального каталога приложения.

Запись состояния и exports выполняется через временный файл в том же каталоге, flush/replace с сохранением предыдущего файла до успешной замены. Исходный пользовательский `.conf` никогда не изменяется. Windows ACL каталога и обычные права текущего пользователя используются вместо macOS-модели `0600`; секреты не записываются в state, history, diagnostics или logs.

## JSON, `AllowedIPs` и AmneziaWG `.conf`

JSON-экспорт остаётся совместимым с AmneziaVPN: записи содержат `hostname`, пустой `ip`, пустой `ips` в соответствии с существующим форматом. Импорт принимает только IPv4/CIDR, пропускает домены без IPv4 и IPv6, показывает строки пользователю до добавления и не отправляет ручные значения в enrichment.

`AllowedIPs` строится из того же выбора, что и JSON. Строка имеет вид:

```ini
AllowedIPs = 1.1.1.1/32, 192.0.2.0/24
```

Результат нормализуется, дедуплицируется семантически, покрытые более узкие сети удаляются, точные соседние сети объединяются только при полном совпадении множества адресов, затем маршруты сортируются по адресу и длине префикса. Пустой выбор блокирует копирование и запись.

Мастер `.conf` принимает один или несколько файлов, позволяет выбрать peer при нескольких `[Peer]` и создаёт для каждого входа отдельный результат `<stem>-iplist.conf` с безопасным уникальным суффиксом. Поддерживаются операции «Добавить к существующим», «Заменить выбранными» и «Пустить выбранное мимо VPN». Исходные IPv6 сохраняются по выбранному правилу; `0.0.0.0/0` обрабатывается с объяснением, что добавление узких IPv4-маршрутов математически не меняет покрытие.

Редактор сохраняет порядок строк, комментарии, пустые строки, BOM, CRLF/LF, наличие финального перевода строки, регистр ключей и неизвестные AmneziaWG параметры. Меняются только строки `AllowedIPs` выбранного peer; при отсутствии строки она вставляется после `PublicKey`. Перед записью проверяются одна `[Interface]`, непустые обязательные ключи, корректные IPv4/IPv6 CIDR, отсутствие дубликатов singleton keys, отсутствие нового неоднозначного overlap с другими peers и непустой итог. Все входные файлы и имена выходов проверяются до пакетной записи; ошибочный файл не повреждает остальные.

`.vpn` не читается, не изменяется и не экспортируется. Он содержит профиль и потенциальные секреты, а список сайтов split tunneling хранится отдельно в клиенте AmneziaVPN; изменение вложенных полей `.vpn` не является эквивалентом редактирования пользовательского списка маршрутов.

Для Full показывается блокирующее по умолчанию предупреждение о размере списка и ограничениях мобильных клиентов. Пользователь может явно подтвердить создание файла для desktop/экспериментального использования. Приложение проверяет синтаксис и объём, но не обещает успешную загрузку тысяч маршрутов на стороннем устройстве.

## Tray, системные функции и приватность

Tray использует стандартный Windows notify icon с действиями открыть окно, проверить сейчас, показать статус и выйти. Системные уведомления являются необязательной оболочкой: отказ Windows notification API не отменяет refresh или export. Файловые операции используют native Open/Save/Folder dialogs; clipboard — системный Windows clipboard.

В логах и сообщениях запрещены private key, preshared key, endpoint credentials, исходное содержимое `.conf` и пользовательские exports. Сетевые запросы ограничены заданными HTTPS URL и RIPEstat, проверяются HTTP-код, размер, timeout и схема ответа. Bundled metadata распространяется с MIT attribution в `THIRD_PARTY_NOTICES.md`; lib4u-данные не вшиваются в репозиторий как пользовательские exports.

## Сборка, CI и артефакт

Windows workflow не изменяет macOS workflow. Он запускается на `windows-latest`, восстанавливает .NET 10 SDK, собирает solution в Release, запускает core tests и публикует `win-x64` self-contained single-file приложение. В workflow проверяются наличие `IPList.exe`, отсутствие зависимости от установленного .NET runtime, наличие bundled resources и создание ZIP с README и SHA-256.

Целевая команда публикации эквивалентна:

```powershell
dotnet publish Windows/src/IPList.App/IPList.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true
```

Название артефакта: `IPList-1.4.0-windows-x64.zip`. ZIP не включает macOS `.app`, пользовательское состояние, `.vpn`, реальные ключи или персональные exports. Публичная публикация GitHub release не является частью этой спецификации.

## Проверка и критерии приёмки

Core tests должны на санитизированных fixtures доказывать:

- разбор категорий, Аэрофлота, `aeroflot.ru`, `api.aeroflot.ru`, AS34571 и явных диапазонов;
- поиск Аэрофлота по названию, домену, ASN и сопоставленному IP;
- корректное включение/исключение сервиса во всех трёх режимах;
- сохранение общих маршрутов при наличии второго владельца;
- полное покрытие каждого Lite/Full source через сервисы или «Остальные сети»;
- сохранение последней успешной модели при сбое каталога, DNS, RIPEstat или подозрительном shrink;
- нормализацию, exact subtraction, collapse, дедупликацию и отсутствие расширения адресного множества;
- JSON совместимость и `/32` в `AllowedIPs`;
- парсинг и byte-preservation `.conf`, операции add/replace/bypass, multi-peer и batch output;
- отсутствие секретов в ошибках, state, history и logs;
- миграцию ручных данных, профилей, расписания и выбора.

Windows smoke acceptance на реальных Windows 10 22H2 и Windows 11 должна подтвердить запуск ZIP без установленного .NET, масштабирование 100/125/200%, поиск и выбор каталога, refresh с cache fallback, import/export JSON, copy/save `AllowedIPs`, single/batch `.conf`, tray, расписание, native dialogs и сохранение состояния между перезапусками. Отдельно проверяется, что macOS `git diff` вне `Windows/` и документации Windows отсутствует.

Релиз считается готовым только при одновременном выполнении всех условий: core tests проходят, Windows CI публикует self-contained ZIP, smoke acceptance пройдена на обеих целевых версиях Windows, а исходные `.conf` и секреты не изменяются и не попадают в артефакт.
