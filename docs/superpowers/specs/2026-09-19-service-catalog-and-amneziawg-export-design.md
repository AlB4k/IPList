# IPList 1.4.0: каталог сервисов и экспорт AmneziaWG

## Цель

IPList должен показывать обновляемый каталог российских сервисов во всех трёх режимах, сопоставлять сервисы с адресами выбранного источника и включать в экспорт только отмеченные сервисы. Обновление не должно незаметно удалять ранее рабочие данные или терять сети исходного списка. Версия 1.4.0 также должна экспортировать выбранные маршруты как строку `AllowedIPs` для вставки в клиентскую конфигурацию AmneziaWG.

## Источники и лицензии

Списки адресов остаются следующими:

- `lib4u/amnezia-tunneling-ru` — `amnezia.json`, `amnezia-ip-lite.json`, `amnezia-ip.json`;
- основной каталог метаданных — `pincetgore/amnezia-app-ru-list/config.yaml`;
- запасной каталог при недоступности сети — последняя успешно сохранённая копия, а на чистой установке — снимок каталога, включённый в приложение;
- префиксы ASN — RIPEstat `announced-prefixes` API;
- адреса доменов — системный DNS macOS и DNS-over-HTTPS Google/Cloudflare с объединением успешных ответов.

`pincetgore/amnezia-app-ru-list` распространяется по MIT. Снимок каталога и использование его структуры должны быть отражены в `THIRD_PARTY_NOTICES.md`, вместе с текстом требуемого уведомления. Данные lib4u не включаются в репозиторий и загружаются во время работы, как и раньше.

## Модель каталога

`CatalogService` содержит стабильный идентификатор, название, категорию, домены, ASN, явные диапазоны и сопоставленные адреса отдельно для `targeted`, `lite` и `full`. Идентификатор строится из источника и нормализованного названия. При переименовании миграция пытается найти прежний сервис по пересечению доменов и ASN.

Категории читаются из секций `config.yaml`. Парсер поддерживает только используемое источником подмножество YAML: список `services`, поля `name`, `asn`, `ip_ranges`, `domains` и заголовки секций в комментариях. Неизвестные поля игнорируются. Загрузка отклоняется, если нет сервисов, имён или доменов/ASN/диапазонов, либо количество сервисов резко падает ниже безопасного порога относительно последней успешной копии.

Существующие записи из `amnezia.json`, которых нет в новом каталоге, сохраняются как сервисы категории «Дополнительные ресурсы lib4u». Диапазоны Lite и Full, которые не удалось связать ни с одним сервисом, сохраняются в специальном выбранном по умолчанию элементе «Остальные сети источника». Таким образом, каждый адрес источника принадлежит хотя бы одному видимому элементу каталога.

## Сопоставление адресов

Для каждого сервиса приложение объединяет:

1. явные IPv4/CIDR из каталога;
2. текущие A-записи доменов;
3. IPv4-префиксы заявленных ASN из RIPEstat;
4. адреса совпавших доменов из `amnezia.json`.

Для точечного режима сохраняются конкретные IPv4 и явные CIDR. Для Lite и Full сервис получает каждый диапазон исходного списка, который содержит найденный IP или пересекается с явным/ASN-префиксом. Один диапазон может принадлежать нескольким сервисам.

После сопоставления проверяется инвариант для Lite и Full:

`объединение адресов всех сервисов + остальные сети источника == нормализованный исходный список`.

При нарушении инварианта обновление не публикуется. Новые данные сначала собираются во временную модель, проходят проверку и только затем атомарно заменяют состояние. Ошибка одного сетевого обогатителя не очищает старые данные сервиса: используется последний успешный результат с отметкой о его возрасте.

Аэрофлот является обязательным приёмочным сценарием: каталог содержит «Аэрофлот», `aeroflot.ru`, `api.aeroflot.ru`, AS34571 и сопоставленные адреса текущего режима. Поиск по названию, домену и IP находит этот сервис.

## Выбор и экспорт

Галочка сервиса действует одинаково во всех режимах:

- установлена — адреса сервиса текущего режима участвуют в экспорте;
- снята — собственные адреса сервиса не участвуют;
- общий диапазон остаётся, если он нужен другому отмеченному сервису;
- «Остальные сети источника» подчиняются собственной галочке;
- «Мои IP» добавляются при включённой существующей настройке.

Все сервисы и «Остальные сети источника» выбраны по умолчанию. Поэтому исходное поведение Full/Lite сохраняется на чистой установке: экспорт содержит весь исходный список. Пользовательские профили и выбор мигрируются. Новые сервисы автоматически выбираются только при включённой политике выбора новых ресурсов; иначе они видимы, но не меняют существующий профиль.

Обычный JSON-экспорт сохраняет формат AmneziaVPN. Перед записью выполняется нормализация и дедупликация.

## Экспорт `AllowedIPs`

Добавляются три действия: «Копировать AllowedIPs», «Сохранить строку AllowedIPs» и «Создать конфигурацию AmneziaWG». Первые два формируют текстовый фрагмент конфигурации из выбранных маршрутов:

```ini
AllowedIPs = 1.1.1.1/32, 192.0.2.0/24
```

Правила формирования:

- используются те же выбранные адреса, что и для JSON-экспорта;
- одиночный IPv4 всегда записывается как `/32`;
- существующий CIDR сохраняет нормализованную маску;
- адреса дедуплицируются и сортируются численно по адресу и длине префикса;
- пустой выбор не создаёт файл и показывает понятную ошибку;
- строка не переносится, чтобы её можно было вставить вместо существующего `AllowedIPs` в секции `[Peer]`;
- интерфейс явно предупреждает: эти маршруты пойдут через VPN. Для режима «мимо VPN» нужен JSON-список исключений AmneziaVPN либо вычисление дополнения IPv4, которое не входит в объём 1.4.0.

Это соответствует семантике AmneziaWG/WireGuard: `AllowedIPs` определяет сети, направляемые к соответствующему peer. Экспорт не меняет ключи, endpoint и параметры маскировки пользовательской конфигурации.

### Обогащение существующей конфигурации

Действие «Создать конфигурацию AmneziaWG» открывает пользовательский `.conf`, разбирает секции `[Interface]` и `[Peer]`, позволяет выбрать peer при наличии нескольких и сохраняет новый файл. Исходный файл никогда не перезаписывается.

Официальный формат допускает несколько `[Peer]`, но это несколько криптографических соседей одного интерфейса, а не список взаимозаменяемых VPN-серверов. IPList не объединяет независимые клиентские конфигурации в один многопировый файл: их `[Interface]` имеют разные приватные ключи и адреса, а одинаковые `AllowedIPs` создают конфликт маршрутизации и не дают выбора сервера. Вместо этого диалог допускает выбор нескольких `.conf` и выполняет пакетное обогащение: для каждого входного файла создаётся отдельный новый файл с тем же именем и суффиксом `-iplist`. Перед сохранением пользователь выбирает выходную папку и видит результат проверки каждого файла.

Редактор работает как структурно осведомлённая точечная замена: он сохраняет исходный порядок строк, комментарии, пустые строки, окончания строк, регистр ключей и все неизвестные параметры AmneziaWG. Изменяются только строки `AllowedIPs` выбранного `[Peer]`. Приватный ключ и остальное содержимое обрабатываются только в памяти, не записываются в состояние приложения, историю или журналы.

Пользователь выбирает одну из трёх операций:

- «Добавить к существующим» — объединить выбранные маршруты с текущими `AllowedIPs`;
- «Заменить выбранными» — записать только маршруты текущей выгрузки.
- «Пустить выбранное мимо VPN» — вычесть выбранные IPv4/CIDR из существующих IPv4 `AllowedIPs`; это режим по умолчанию, соответствующий основной задаче IPList.

При существующем `0.0.0.0/0` добавление IPv4-маршрутов математически ничего не меняет, поэтому приложение объясняет это и предлагает замену или вычитание. Режим «мимо VPN» вычисляет точное CIDR-дополнение внутри уже существующих разрешённых IPv4-сетей и не расширяет исходную область маршрутизации. `::/0` и другие IPv6-маршруты сохраняются в режимах добавления и вычитания; в режиме замены пользователь отдельно выбирает, сохранять ли существующие IPv6-маршруты. Если `AllowedIPs` отсутствует, строка вставляется после `PublicKey` выбранного peer. Повторяющиеся строки `AllowedIPs`, которые официальный Apple-парсер допускает и объединяет, сводятся в одну строку.

Перед сохранением выполняется независимая проверка результата: одна секция `[Interface]`, непустые `PrivateKey`, `[Peer]` и `PublicKey`, корректные IPv4/IPv6 CIDR в `AllowedIPs`, отсутствие повторяющихся одиночных ключей внутри секции и сохранность всех строк, не относящихся к изменяемому `AllowedIPs`. При ошибке новый файл не создаётся.

### Ограничения мобильных устройств

Перед экспортом показываются число маршрутов и размер итоговой строки после выбранной операции. Для Full выводится блокирующее по умолчанию предупреждение: текущий список содержит около 12 800 маршрутов, а авторы источника прямо указывают, что мобильные клиенты Android/iOS на таком объёме могут не поднять туннель. Вычитание полного российского списка из `0.0.0.0/0` ещё тяжелее: на проверенном снимке оно даёт около 30 000 маршрутов. Создать такой файл всё же можно отдельным подтверждением для настольного клиента или экспериментального использования.

Для смартфона интерфейс рекомендует Lite либо выбранные сервисы. Приложение не обещает универсальный числовой предел: он зависит от ОС, версии клиента и устройства. Оно проверяет синтаксис файла, но не может гарантировать успешную установку тысяч маршрутов на другом устройстве.

## Обновление и интерфейс

«Проверить сейчас» обновляет каталог и все три адресных источника одной транзакцией. Расписание делает то же самое. Экран диагностики показывает отдельные результаты для каталога, Targeted, Lite, Full, DNS и RIPEstat, а также время последнего успешного обновления и использование сохранённого кэша.

Каталог отображается во всех режимах. Строка сервиса показывает число сопоставленных адресов текущего режима, число доменов и состояние данных. Поиск работает по названию, домену, ASN, конкретному IP и CIDR. При отсутствии результатов интерфейс сообщает, загружен ли каталог и когда он обновлялся.

Категории по умолчанию свёрнуты. Счётчик категории показывает `выбрано/всего`. «Выбрать все» охватывает сервисы, дополнительные ресурсы и «Остальные сети источника».

## Миграция и сохранность данных

Состояние 1.3.x декодируется без потерь. Ручные IP, группы, заметки, история, расписание и профили сохраняются. Старый каталог остаётся доступным до первой полностью успешной транзакции 1.4.0. Перед миграцией создаётся резервная копия `state-before-v1.4.json`.

История фиксирует изменения исходников отдельно от изменений итоговой выгрузки. Неуспешное обновление не меняет `last successful`, каталог, выбор и автоматически сохранённый экспорт.

## Структура реализации

Чтобы не увеличивать уже крупные `Core.swift` и `App.swift`, код разделяется по ответственности:

- `CatalogModels.swift` — модели каталога и миграция;
- `ServiceCatalogLoader.swift` — загрузка и разбор конфигурации;
- `AddressMatcher.swift` — IPv4/CIDR, пересечения и сопоставление;
- `EnrichmentLoader.swift` — DNS и RIPEstat с ограниченной параллельностью и кэшем;
- `ExportFormats.swift` — JSON и `AllowedIPs`;
- `Core.swift` — состояние и совместимость;
- `App.swift` — управление транзакцией обновления и SwiftUI;
- `Tests/CoreChecks.swift` и дополнительные тестовые файлы — поведенческие проверки.

Внешние Swift-зависимости не добавляются.

## Проверка и критерии релиза 1.4.0

Автоматические проверки должны доказывать:

- парсер извлекает категории, Аэрофлот, домены, ASN и диапазоны из фиксированного фрагмента источника;
- поиск находит Аэрофлот по `Аэрофлот`, `aeroflot.ru`, AS34571 и сопоставленному IP;
- галочка включает и исключает адреса во всех режимах;
- общие диапазоны не удаляются преждевременно;
- каждый входной диапазон Lite/Full находится либо у сервиса, либо в «Остальных сетях источника»;
- сбой DNS, RIPEstat или каталога не обнуляет последнюю успешную модель;
- миграция сохраняет ручные данные, профили и выбор;
- `AllowedIPs` добавляет `/32`, сохраняет CIDR, сортирует и дедуплицирует;
- обычный JSON-экспорт остаётся совместимым;
- живой тест загружает актуальные источники и находит Аэрофлот;
- приложение собирается как версия `1.4.0`, запускается, обновляет данные и создаёт оба формата экспорта.

Перед релизом обновляются README, THIRD_PARTY_NOTICES, PUBLISHING, снимки интерфейса и журнал изменений. Создаётся локальная подписанная ad-hoc сборка; публикация и отправка в GitHub не выполняются без отдельного указания пользователя.

## Исследование `.vpn` для будущей версии

Нативный файл `.vpn` AmneziaVPN содержит строку `vpn://`: URL-safe Base64 без padding, внутри `qCompress` (четыре байта исходной длины и zlib), затем JSON профиля сервера. Официальный `amnezia-vpn/config-decoder` подтверждает этот алгоритм.

Список сайтов встроенного раздельного туннелирования не является частью экспортируемого серверного профиля. В текущем клиенте он хранится в настройках приложения (`Conf/routeMode`, `Conf/sitesSplitTunnelingEnabled` и карта сайтов) и добавляется в рабочую VPN-конфигурацию во время подключения. Более того, интерфейс раздельного туннелирования разрешается только для профиля с полным `AllowedIPs`, содержащим одновременно `0.0.0.0/0` и `::/0`.

Технически IPList мог бы декодировать `.vpn`, изменить вложенные `allowed_ips`/`last_config` и снова закодировать профиль, но это создало бы частичный маршрут самого подключения, а не предварительно заполненный список сайтов в интерфейсе AmneziaVPN. Формат также содержит секреты и меняется вместе с версиями AWG. Поэтому поддержка `.vpn` не входит в 1.4.0. Для будущей версии требуется отдельная совместимость по версиям профиля и проверка импорта на каждой поддерживаемой платформе.
